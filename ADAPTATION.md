# Worker Frens launch adaptation

## Scope and result

The existing implementation already provides the four constructor deployments requested by the brief:

| Order | Contract | Constructor arguments |
| --- | --- | --- |
| 1 | `PlaceFrens` (`src/FrensPlacement.sol`) | None |
| 2 | `WorkerArt1` (`src/art/WorkerArt.sol`) | None |
| 3 | `WorkerArt2` (`src/art/WorkerArt.sol`) | None |
| 4 | `PlaceModules` (`src/FrensPlacement.sol`) | `$contract:PlaceFrens`, `$contract:WorkerArt1`, `$contract:WorkerArt2` |

These constructors are nonpayable. The collection and gate belong to
`0x35dA9C0303507ddf708E87F2568EdDf12c47a059`; the collection's initial governor is that same wallet.
The launch retains no role. The price and art data contracts, renderer, minter and swapper have no independent owner
role to transfer. The keeper, relayer and job payee remain the brief's pinned values.

No production Solidity, creation-code data, salts, art, build configuration or dependencies were changed. In
particular, the collection remains `0x69006841041E7519fbE54BfF3F506FBDCAbabF09` and the swapper remains
`0x6900d1D4BcF96143C6013AF72F319Ad401e7928a` when the standard CREATE2 deployer is present. No manifest, launch token,
new dependency or broadcast was introduced.

**The audit findings below are not repaired.** The brief expressly prohibits changing `src/frens/`, `src/FrensCode.sol`
and `src/FrensPlan.sol`. Repairing the collection's accounting or permissions, or the swapper's price initialization,
would change the pinned creation code and addresses. A wrapper cannot alter those internal decisions, and rejecting
an already placed swapper alone would not fix initialization from a manipulated spot price. The explicit fixed-code
requirement was preserved. This deliverable supplies deployment verification and reproducible evidence; it does not
claim to satisfy the conflicting requirement to fix every reproduced audit finding.

## Changes

- `test/FrensLaunchReview.t.sol`: adds a constructor-only CREATE2 factory with the interface and limits of the supplied
  protected probe, compiled with the project's existing compiler. Tests deploy all four applications in order using
  their actual artifacts, check predicted factory addresses, runtime sizes and dependency/role assignments, and
  verify that factory/launch addresses cannot exercise admin rights. A fresh-chain trace checks all ten creations
  (four applications and six nested contracts), rejects forbidden execution modes, and checks that calls target only
  newly created dependencies, apart from the test's own factory and cheatcode calls.
- The same test file adds persistent reproductions of the imported findings, including an exact-address swapper
  predeployment accepted by the launch. Collection tests use `PlaceFrens`' actual generated bytecode and price table;
  external tokens, swaps and Permit2 are local fixtures. The IMD fixture uses explicit allowances, disabling the
  Solady mock's default infinite allowance at the canonical Permit2 address. These tests assert the observed defects
  and trust assumptions, **not their remediation**.
- `README.md`: distinguishes factory deployment from the explicitly required team-wallet setup; corrects the claim
  that identical creation code necessarily produces equivalent storage; links the audit evidence and its limits.
- `ADAPTATION.md`: records the changes, requirement conflict, finding dispositions and validation.

## Imported audit dispositions

1. **`f338bd7ad4bcd596bbed40351b84cd2f9f79e62c0963ff2afbf1a888242ead63` — setup after deployment.**
   Reproduced by `test_Audit_ConstructorLeavesTheDocumentedTeamSetup`: renderer, swapper and gate are zero;
   traits are unsealed, minting is closed, art is not frozen and the gate has no WL root. A governor mint fails with
   `TraitsNotSealed`. The specific reported `tokenURI(1)` explanation does not reproduce immediately after launch:
   it fails with `TokenDoesNotExist`, before reaching a renderer, because no token has been minted. The setup
   dependency itself is real. The task explicitly requires the team wallet to run `DeployFrens.setup()` after launch,
   so that boundary is retained. The factory does not initialize, open or freeze the collection. Setup, WL
   configuration, opening and the timelock batch remain team/governance actions.

2. **`4def4296fbe526310d7c6e8abb7c801ed175f4431fc95efb6b238cee0069e8a6` — transfer freezing and mint closure.**
   Reproduced by `test_Audit_OwnerOrGovernorCanBlockAllPeerTransfers` and
   `test_Audit_GovernorCanCloseMintAgain`. With owner and governor separated, either can install an always-reverting
   validator that blocks holder `transferFrom`, `safeTransferFrom` and an approved operator. Recycling still works.
   The governor can close an already-open mint. These powers remain in the pinned collection; a launch wrapper
   cannot remove them or make a one-time validator setting irreversible. They remain unresolved policy conflicts
   and trust assumptions, not capabilities purportedly eliminated by this adaptation.

3. **`992a6ec3a77fa460fe3fd213ebaa84c48b66b9aed52cfff1bb42b5a6bb27203c` — empty-world mint bypasses the floor.**
   Reproduced by `test_Audit_EmptyWorldMintExtractsTheReserve`. After the sole holder recycles, the mock ETH route
   credits a reserve worth 750 IMD. `floorPerFren()` correctly reports that whole reserve, but `quote(1)` returns the
   next curve price. A new mint followed by recycling extracts the reserve. Buying an existing treasury token then
   costs zero because the reserve has been emptied. The report's broader implication that treasury purchases are
   free while a nonzero reserve remains does **not** reproduce: the existing `out == 0` fallback in `floorPerFren()`
   charges twice that reserve. The quote defect remains unresolved inside the pinned collection.

4. **`0640f0a65a9f75a31858a93c1266412934d7f615844bcd8921afe2924a1d3b99` — expired job approval remains booked.**
   Reproduced by `test_Audit_ExpiredJobApprovalRemainsAfterFullReveal`: approve an unpaid job, pass its deadline,
   then fully reveal using a relayer signature. Reapproval fails with `BadJob`; 0.5 IMD stays in the collection,
   outside `floorImd` and `jobBudget`, but inside the outstanding allowance. The permit digest still passes ERC-1271,
   and a later floor buy cannot absorb the amount. A real Permit2 deadline still needs to be enforced by Permit2;
   this offline fixture does not settle a payment. No external wrapper can call the private cleanup path after the
   completed-request guard. The accounting defect remains unresolved in the pinned collection.

5. **`ca830bfe4f63e1ea285c99c7014ab676abed2aeaa1dc162dc91a2e80e8839f6a` — deployment-block swapper average.**
   Reproduced by `test_Audit_LaunchAcceptsSwapperSeededAtManipulatedSpot`. A pool slot0 fixture at `2^96 / 26`
   seeds the actual planned swapper at approximately 676 IMD6900 per IMD. After restoring slot0 to `2^96 / 265`
   (approximately 70,225), a later launch adopts that same address and retains its average and deployment block.
   Its floor rate stays over 100 times lower than spot, raising the collection's reserve valuation accordingly.
   The test covers state initialization, adoption and quote impact; it does not claim to execute a real pool
   manipulation or prove the audit's dust-trade economics. The source has no minimum-volume check in `_average`,
   but a live dust swap may round to zero. The initialization finding remains unresolved. Controlling launch timing
   is only an operational mitigation, not an on-chain fix.

6. **`364f15a23258f3a934ebe7edc1df1ff0def03782e1798ad17c9498da56d2de01` — coverage.**
   Informational, not a defect. Read the supplied protected test, pinned security guide and licence, placement,
   plan, collection, modules, deployment scripts and relevant tests. Source/creation-code equality, art data and
   opcode scans are exercised by the existing tests. Local mocks do not verify mainnet contracts or pool behavior.
   No Slither, Mythril, explorer verification, live deployment or gas-price policy check was performed.

## Validation

Using the unchanged `foundry.toml`, Foundry 1.8.3 and solc 0.8.30:

- `forge build --offline`: passed, including the initial full compilation and the final incremental build.
  Existing compiler/lint warnings remain.
- `forge test --offline`: **119 passed, 0 failed, 5 skipped**. Eight passing tests are new. The five mainnet fork
  suites skip in `setUp()` because `MAINNET_RPC_URL` is unset; the reference renders, live pools, validator,
  Permit2/x402 and timelock integration were therefore not verified against Ethereum in this environment.
- The passing existing tests include `test_CodeIsWhatTheSourcesBuild`, `test_PlanFollowsFromTheCode`,
  `test_DeploysOnAFreshChain`, `test_FitsOneTransaction`, `test_PassesTheAdmissionScan` and
  `test_NewArtReadsBackExactly`.
- Actual artifact initcode lengths, including `PlaceModules`' three arguments: `PlaceFrens` 40,506 bytes,
  `WorkerArt1` 28,472 bytes, `WorkerArt2` 21,869 bytes, `PlaceModules` 42,930 bytes. The existing transaction
  test passes the separate per-deployment `2^24` gas checks. Aggregate test gas for a whole four-contract launch
  is not a single deployment's transaction gas.

No external dependency was installed. Tests require neither the removed `.imd/reads` inputs nor `test/scratch/`.
Passing reproduction tests and the opcode admission scan are not an independent security audit or resolution of
the findings above.
